# AI HTML 生成链路

## 为什么改

旧工作台的海报由本地 SVG 布局函数生成，StepFun 只修改文案。新主入口将版式创作移至模型：活动需求 + 独立风格预设 → StepFun 完整 HTML/CSS → 内容/安全检查 → Chromium PNG。旧模板工具保留为独立次级入口。

## 接口

| 接口 | 用途 | 调用外部 API |
|---|---|---|
| POST /api/chat | 对话问答、需求整理、生成/修改意图 | 是；生成时转交 HTML 任务 |
| GET /api/assets | 素材目录与授权信息 | 否 |
| GET /api/styles | 自由创作及六种参考风格与版本 | 否 |
| POST /api/generations | 新建/修改设计，返回任务 ID | 是，初次设计一次，必要时最多追加两轮纠错 |
| GET /api/generations | 本机作品库 | 否 |
| GET /api/generations/{id} | 查询真实阶段及结果 | 否 |
| GET /api/generations/{id}/image | 完成作品 PNG | 否 |
| GET /api/generations/{id}/source | 实际 HTML 与预设 | 否 |
| POST /api/generations/{id}/rerender | 有模型输出的失败任务重新校验、渲染 | 否；自动修复明确的资源声明/事实标记，随后严格校验和渲染 |
| POST /api/generations/{id}/retry | 按原需求建立新生成任务，保留失败记录 | 是；独立幂等键 |
| GET /api/generations/{id}/package | HTML、PNG、字体、素材授权、记录 ZIP | 否 |

POST 必须携带 Idempotency-Key；同 key 同内容返回原任务，不再次扣费。不同内容复用 key 返回409。revision_of 带入原图和实测排版；精细调整/明显改版还带入原 HTML，全新方案不带旧 HTML。返回新任务且不覆盖原作。修改输入主要用于视觉调整，原通知中的标记事实仍受保护。

任务状态 queued → designing → checking → rendering → complete。交付校验失败时进入 repairing，将实际错误和原设计交给同一个模型修复，最多追加两轮；仍不通过才进入 failed。先进行不收费的本地修复：识别常见事实标签别名、拆开日期与 TIME 等标签、修复可见区缺失/重复的字段标记、恢复明确的事实、移除不允许的 CSS 资源声明。无法明确判断的内容交给模型修复。每轮输出与错误均保留，不用固定模板冒充成功。每次模型请求有独立预算账本并累计用量；预算不足、模型服务报错或网络状态未知时停止自动调用。PNG 需存在、格式及尺寸正确，才原子发布并标记 complete。重启后将未完成任务标记中断，未知费用保持预留；前端恢复轮询不会重新提交模型请求。

## 本机资源

- FastAPI + httpx + SQLite 记录与费用预留。
- Playwright Chromium，固定画布1080×1440、1080×1080、1920×1080。
- PosterSans、PosterSerif、PosterDisplay 三套真实中文字体及授权文件，部署需包含 web/public/fonts。
- 生成文本、PNG 和原始模型响应保存在本机 studio-data，默认不进 Git/源码交付。
- 需求整理：step-3.5-flash；设计和改版：step-5-preview，高推理强度、输出上限65536 tokens、超时600秒；视觉评测：step-5-preview，中等推理强度、上限16000 tokens。模型及设计推理强度可用环境变量配置。
- 原生 HTML 输出避免把长代码包进 JSON 的转义损坏；设计思路、摘要和变化用 head 中的 meta 元信息承载。design-request.json 保存实际提示词，源码包可追溯。
- 未知模型价格不套用旧模型费率；记录真实 token 用量，费用以供应商账单为准。本地预算为预留机制，不是平台余额或严格的实际花费上限。

## 防护和限制

创作模式允许静态 SVG、渐变/滤镜/图案、伪元素和安全 CSS @规则；继续禁止脚本、外链、非白名单图片、iframe、事件属性与 SVG 外部资源。渲染时再次用 CSP、禁用JS与请求白名单隔离。本地修复不重做艺术构图；渲染时只注入字体和基础排版兜底（正文32px、主标题72px；模型显式字号优先），不重排生成的版式。对显式设置过小的文字仍会拒绝。

日期等标记字段必须原文一致。渲染检查画布大小、字段是否越界/溢出/重叠与最小字号（正文24px、标题48px）。人工仍需判断审美、低对比和装饰遮挡。自由文本中的无标签事实无法完整自动验证。

这是本机个人工具。多用户部署还需认证、作业队列、进程资源上限、供应商并发/配额控制和备份策略。

## 对话与 Canvas

主入口从参数面板改为对话。首页以输入框和「发送」为核心，附带场景、需求助手、素材三个可选入口与灵感卡片。问答时保持聊天布局，创建任务后自动打开大画布。桌面左右为对话和海报，手机切换「对话 / 画布」；发送入口固定在对话底部，不再要求滚动寻找开始按钮。

`chat.py` 使用文本模型判断 reply/design。reply 直接返回自然语言；design 将对话整理为完整事实 brief + 视觉 instruction，交给已有 HTML 生成器。已有作品的事实修订会体现在新的 brief 中，因此「改日期」也能通过精确信息校验。不能保证模型永不误解，发布前仍需人工核对。

对话调用与生成调用各自使用幂等账本。重试同一请求先复用保存的对话决策，再复用生成任务 ID。网络不确定时不自动重发。可识别的参数或回复错误显示友好提示并恢复输入；未知提交保留原请求标识供手动恢复。

对话存储在浏览器 localStorage；服务器保存生成记录。首次进入将旧作品链导入对话列表，不删除原数据。模型收到初始需求、最近对话以及当前选中画布的事实；长对话超过输入限额时明确提示。历史版本可以重新选为修改起点。

风格/尺寸收在「创作偏好」，源码/提示词收在「作品详情」，旧版模板功能收在侧栏的「服务与工具」。


## 创作工具与素材（2026-10-29）

- `creative-model.ts` 定义六类场景的字段、提示词组装、九类优化维度、品牌上下文、素材选择与备份验证。
- `CreativeTools.tsx` 承载按需打开的工具弹窗，保持主界面为对话 + Canvas。需求助手和场景表单提供明确生成按钮，确认后的文字进入对话并直接提交；优化工具也可直接生成新版。
- `POST /api/chat` 的 `mode=plan` 使用独立需求编辑系统提示词。后端强制只回复，不会进入生成队列，即使模型误返回 design。需求助手一次模型调用；生成/修改通常两次。
- `asset_ids` 最多6项，最多1个背景。聊天请求省略此字段时继承当前作品素材，显式空数组清除。UI 把所选 ID 显式提交；切换历史画布会恢复其素材选择。
- 素材目录来自 `web/public/library/catalog.json`，当前24款双色图标、8张原创背景。Lucide SVG由已安装官方包导出，背景为本项目原创SVG，预先离线转PNG。运行时不接受用户文件路径。
- 生成模型获得所选素材清单与路径，必须使用 `img[data-asset]`，同一素材可重复作为装饰图案。校验器检查登记路径、必选图像、画布内位置、尺寸和显隐；渲染器仅放行本地PNG与字体。图片加载失败会报错。装饰遮挡与美学仍需人工检查。
- 源码包包含所选PNG与 `assets/LICENSE.txt`。Lucide图标许可证来源 https://lucide.dev/license ，部分派生图标保留 Feather MIT；原创背景按CC0提供。Hero Patterns只提供外部参考链接，未打包其素材。
- 可复现素材构建：`node web/scripts/create-library.mjs` 与 `.venv/bin/python tools/render_library.py`。
- `/api/generations` 不再只显示最近100条；所有本机版本可见。下一阶段多用户场景应换为服务端分页、按会话查询与队列并发限制。
- 品牌偏好、提示词收藏、动效设置和素材草稿存在浏览器。JSON对话导入限制10MB并做Zod结构验证；不覆盖已有ID，不执行导入文本。导出不包含图片、品牌或收藏。

## 下一阶段产品与资源

当前重点是完整创作闭环。适合后续扩展的方向：活动物料多尺寸组合、品牌字体与标志管理、参考图提取视觉方向、协作批注、版本选优记录，以及带实际二维码的营销物料。新功能继续采用可选工具，避免占满聊天主界面。

正式提供多用户商业服务需要独立建设：账号和租户隔离、服务端会话与对象存储、作业队列与资源限制、实际账单/配额、监控与备份、部署和素材来源审核。当前没有实现这些基础设施，也没有声称已上线SaaS。图片生成、联网图库、参考图理解如需接入，会增加对应的图像/视觉API费用与来源授权要求；本版使用 StepFun 文本与多模态 API，以及本地免费素材和模型生成的 SVG 插画。
