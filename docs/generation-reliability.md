# 海报生成交付修复记录

验证日期：2026-10-29。

## 发现的问题

- 模型返回了可用设计，但 CSS 中的数据图片、缺失或重复的字段标记使整个任务失败。
- 「活动主题」「举办地点」没有归一化为标题和地点，降低了事实校验与纠错的准确性。
- 模型把 TIME 等说明标签放进精确日期字段，或在隐藏区重复添加字段。
- 只请求一次模型，遇到代码截断、文字重叠、布局越界就终止；原来的重新渲染只是重复同一失败步骤。
- 浏览器只在第一次启动时导入服务端作品，后来的任务可能在历史列表中不可见。

## 新流程

1. 保留原始模型响应，先处理明确可修复的资源声明与字段标记；不使用固定模板替换模型的构图。
2. 严格核对已确认事实和静态文档安全要求。
3. 用隔离 Chromium 实际渲染并检查文字可见性、字号、重叠、越界及图片尺寸。
4. 遇到代码或排版错误，把具体错误、原需求与原设计交还给同一个模型，最多追加两轮纠错。
5. 每次模型调用单独记账并累计用量；预算不足或远端状态未知时停止自动请求。价格未知的模型不套用其他模型的价格。
6. PNG 文件存在、可解码且尺寸正确后，才发布文件并显示完成。失败记录不伪装成成功。
7. 失败卡片提供「本地修复并出图」和「按原需求重新生成」。刷新页面会恢复服务端缺失的任务，保留已有会话。

## 实际验证

### 已失败的作品恢复

使用用户本机保留的原始设计，自动移除不支持的数据图片声明、修正事实别名、标记可见标题、分离信息标签、处理隐藏重复字段。通过内容与真实渲染检查，得到 1080×1440 PNG。没有再次调用模型。真实活动资料仅保存在用户本机，不纳入公开仓库。

### 新建作品：南瓜与星光

在网页新对话中选择 Step 3.7 Flash，输入：

```text
请直接生成一张原创万圣节海报。活动主题：南瓜与星光
活动时间：2026年10月30日 19:00—21:00
举办地点：校园活动中心
要求：暗紫、暖橙、薄荷绿，原创南瓜灯和星空插画，富有想象力的构图与有层次的大标题。保留全部活动信息，不增加未提供的事实。
```

点击「发送消息，交给 AI」。首次设计的输出达到当时 24,000 tokens 上限，HTML 未闭合；系统自动进入第一轮纠错。第二次响应完整，成功生成原创南瓜插画海报，并在 Canvas 中显示下载入口。

- 设计任务开始：12:32:04；完成：12:37:31，北京时间，约 5 分 26 秒。包含初次失败和自动纠错；不作为正常速度保证。
- 设计调用：2 次（初次 + 1 次纠错）；另有前序对话整理调用。
- 设计阶段累计：输入 11,755 tokens，输出 32,731 tokens；实际费用以供应商账单为准。
- 输出：1080×1440 PNG，标题、日期、时间、地点通过可见性和排版检查。
- 没有手工改模型生成的艺术构图，没有固定模板兜底。

## 自动检查

GitHub Actions 已通过 100 项后端测试、20 项前端测试与生产构建。覆盖字段别名/隐藏重复/标签拆分、资源清理、安全规则、模型代码修复、实际渲染错误反馈、截断修复、重试幂等性、预算限制、网络状态未知、Chromium 临时故障和无 PNG 不报成功。

## 输出截断的进一步修正

上述实测暴露了旧版 24,000 tokens 输出上限问题。根据 [StepFun Chat Completions 官方说明](https://platform.stepfun.com/docs/zh/api-reference/chat/chat-completion-create)，省略 max_tokens 时由模型自行决定，输入与输出总量仍受模型上下文限制。本版已对全部设计、修改和自动纠错调用省略该参数，保留高推理强度；对话和评测仍使用各自限额。服务请求超时仍为600秒，网络或模型侧中断不能靠输出配置保证消失。
