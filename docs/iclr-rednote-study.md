## 生成器可使用的编辑规则

| 用户拿到什么 | 后台怎样选择内容 | 样本中怎样使用 |
| --- | --- | --- |
| 一开始就能理解的研究问题 | 摘要或引言提供失败情境时，写清谁在做什么、哪一步失效。材料缺少具体情境时，直接提出研究问题。 | LongHorizonUI 使用商城购物和装备道具的连续任务，IGPO 从 GRPO 同组全对或全错导致的学习信号消失切入。 |
| 能说清楚的方法 | 保留方法原名，并用动词讲清比较、保留或改变了什么。示意例子须能追溯到上传内容。 | ConCM 用喙和羽毛说明属性记忆，IGPO 用相邻检索轮次估计奖励，LongHorizonUI 拆开感知、反思和重试。 |
| 可核实的结果 | 优先保留测试范围、比较对象及指标名称。缺乏基线不写“提升”，缺乏实验结果时用方法或局限作主线。 | Vision-R1 把模型规模、MathVista 基准和 73.5% 写在一起。DefensiveKV 区分旧基准和新评测的成绩。MM-ISTS 笔记缺少支持“广泛有效”的数字，是需要把结论收窄的反例。 |
| 与用户材料一致的结尾 | 有论文、代码、视频或展板信息就给读者下一步，缺少真实入口就收在研究发现上。 | CopyPaste 分清本项工作对应的配图，结尾给论文和代码，四工作同帖用展板号让参会者找到具体研究。 |
| 有内容的图注 | 纸面输入有图号、图题或明确的看图说明时，把“看什么、比较什么、能看出什么”连成一句，只读了摘要时不编造配图。 | StableToken 指引读者到 p2 看扰动、p3 看方法，显著性论文让读者比较图上正确和错误答案的差别。 |
| 可直接发布的小红书稿 | 标题与正文分段。优先让读者从标题认出研究对象或具体矛盾。默认由作者分享自己的工作。选择第三方推荐时，交代是谁做的、哪一点值得转给读者。投稿经历、展位或 Oral 等录取类别须有文字依据。 | FlexiCodec 的作者可以讲自己首次投稿的经历。第三方介绍 DiffuDETR 时，一句解释参考点怎样去噪，再给读者官方海报与项目页。 |

这些规则用于编辑和校验。样本限定于 ICLR 2026 相关工作，阅读量与封面风格的关系未经测量。
